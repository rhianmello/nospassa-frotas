Pagamentos do XRMOVI: Conferindo liberação de compras…
Verificações para liberar pagamentos públicos

Essa limitação é uma proteção do próprio XRMOVI para testes, não uma lista de clientes autorizados pelo Mercado Pago. Após a liberação, qualquer cliente cadastrado poderá contratar por Pix ou cartão.

  1. Em Mercado Pago → Integrações → Webhooks, confira a assinatura secreta da mesma aplicação que recebe os pagamentos. Notificações com HTTP 401 não foram validadas e precisam de correção antes da venda pública.
  2. Em Supabase → Edge Functions → Secrets, confira se XRMOVI_MP_WEBHOOK_SECRET corresponde à assinatura do Mercado Pago. Não cole esse segredo aqui, no GitHub ou no suporte.
  3. Teste a entrega de um evento real existente: o webhook deve retornar HTTP 200 e a assinatura deve ser ativada automaticamente, sem intervenção manual ou nova cobrança.
  4. Somente após o teste, configure XRMOVI_BILLING_PILOT_ONLY como false no Supabase Secrets. Isso libera pagamentos a todos os clientes cadastrados, sem autorizar e-mails individualmente.

O login do cliente continua obrigatório. A configuração de avisos de suporte por e-mail abaixo é independente dos pagamentos.

Avisos de suporte por e-mail: Verificando provedor de envio…
Ativar notificações por e-mail e recuperação de senha

O servidor já possui a fila e o processamento automático. Para habilitar o envio é necessário vincular o Resend a um domínio verificado. Nunca informe sua chave privada neste site.

  1. Entre no Resend → Domains, adicione seu domínio (por exemplo, nospassa.com.br) e publique no seu DNS os registros informados pelo provedor. Aguarde o status de envio verificado.
  2. Em Resend → API Keys, crie uma chave com permissão apenas para envio (Sending access).
  3. Na área de Secrets do Supabase, cadastre XRMOVI_RESEND_API_KEY com a chave privada e XRMOVI_SUPPORT_MAIL_FROM com um remetente do domínio verificado, por exemplo XRMOVI <avisos@nospassa.com.br>.
  4. Para o cliente recuperar a senha, habilite o SMTP personalizado em Supabase → Authentication → SMTP Settings, usando host smtp.resend.com, porta 465, usuário resend e a chave de envio como senha. Remetente sugerido: acesso@nospassa.com.br, após verificação do domínio.
  5. Em Supabase → Authentication → URL Configuration, autorize exatamente https://frota.nospassa.com.br/redefinir-senha.html e teste com uma conta de homologação.

Os novos avisos de suporte serão enviados para o e-mail do proprietário já configurado no servidor. A configuração não gera cobrança Mercado Pago.
